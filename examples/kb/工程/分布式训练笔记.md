## 为什么要并行

单卡放不下是常态：一个 7B 模型用 FP16 存权重就要 14GB，训练时还要梯度和优化器状态，
加起来 112GB（构成见下面「ZeRO」那节）。所以并行不是"为了更快"，多数时候是"不然跑不起来"。

并行的三个维度各管一件事：

- **数据并行（DP）**：每张卡一份完整模型，喂不同的 batch —— 解决的是**吞吐**。
- **张量并行（TP）**：把单层的大矩阵切开 —— 解决的是**单层放不下**。
- **流水并行（PP）**：把不同的层分到不同的卡 —— 解决的是**整体层数太多、单卡装不下整个模型**。

选哪个取决于"哪里放不下"：单层放不下用 TP，整体放不下用 PP，都放得下但太慢用 DP。
真实训练里三者一起用，叫 3D 并行，总卡数 = TP × PP × DP。

## 数据并行与梯度同步

每张卡有一份完整模型，各自算 loss 和梯度，反向结束后**把梯度 all-reduce 求平均**，
然后各自更新——这样所有卡的参数永远一致。

通信量 = 参数量 × 梯度字节数。7B 用 FP16 梯度就是 14GB **每一步**。
所以工程上要做两件事：把梯度打成桶（bucket）批量发，以及让通信和反向计算重叠（overlap）。
PyTorch 的 DDP 默认就做了这两件事。

**梯度累积不省通信**：攒 4 步再更新，仍然是每步一次 all-reduce，只是把更新频率降下来。
它省的是"优化器状态更新"的那点开销，不是通信。这是最常见的误解之一。

## 张量并行（TP）

把一层的权重矩阵按列切成 N 份，分到 N 张卡，每张卡算一部分输出，再 all-reduce 拼起来。
一层里通常要做**两次**通信（进入和出来各一次），层数越深通信次数越多。

所以 TP 的硬约束是**通信带宽**：必须同机 NVLink，跨机做 TP 基本一定亏（通信把收益吃光）。
实践中 TP 度数一般不超过单机卡数（8）。

## 流水并行（PP）

把模型的层按顺序切给不同的卡，一个 batch 再切成若干 micro-batch 依次流过，
形成"流水线"。用 1F1B（一前一后交替）能显著减少空转。

流水线的空转比例（气泡率）约等于 **(p−1)/(m+p−1)**，p 是流水段数、m 是 micro-batch 数。
所以：段数越多、micro-batch 越少，气泡越大。想压气泡就得把 micro-batch 数量加上去。

## ZeRO 的三个阶段

先把"每参数占多少字节"算清楚（Adam + 混合精度）：

| 项目 | 每参数字节 |
|---|---|
| FP16 权重 | 2 |
| FP16 梯度 | 2 |
| FP32 主权重 | 4 |
| Adam 的一阶动量 m | 4 |
| Adam 的二阶动量 v | 4 |
| **合计** | **16** |

7B × 16 = 112GB —— 这是"一张卡什么都不切"的情况。

ZeRO 的思路是**把这三样东西按卡数 N 切开**：

- **ZeRO-1**：只切优化器状态 → 每参数 `2 + 2 + 12/N`
- **ZeRO-2**：再切梯度 → `2 + 2/N + 12/N`
- **ZeRO-3**：连权重也切 → `2/N + (2+12)/N`

取 N = 8、7B 模型，按上面的式子算（7B × 每参数字节）：

- ZeRO-1：5.5 字节/参数 → 约 **38.5GB**
- ZeRO-2：3.75 字节/参数 → 约 **26.3GB**
- ZeRO-3：2.0 字节/参数 → 约 **14GB**

这些是**理论值**，实现还会额外占显存（激活值、通信缓冲、碎片），实际要再留一截余量。
另外 ZeRO-3 每层都要临时聚合参数，通信量比 ZeRO-1/2 大得多 —— 省显存是拿带宽换的。

## 怎么配

经验顺序：

1. 先看**单机**能放下几卡 TP（一般 ≤ 8，看有没有 NVLink）；
2. 单机放不下整个模型就加 PP，把层切到多机；
3. 最外层套 DP 提吞吐；
4. ZeRO-1 或 ZeRO-2 基本是"免费的省显存"，优先开；ZeRO-3 只在真的差显存时上。

## 五个常见的坑

1. **TP 跨机**：通信量太大，实测收益为负，别试。
2. **micro-batch 太小**：流水气泡能占到一半以上，GPU 利用率看着像没在跑。
3. **把梯度累积当成省通信**：不省，见上面那节。
4. **只开 ZeRO-3、不开 offload**：通信暴涨，速度可能还不如 ZeRO-2。
5. **冻结层 + DDP**：`find_unused_parameters` 没设对会直接卡住或报未使用参数错误。

## 一句话总结

显存问题用"切"（TP/PP/ZeRO），速度问题用"堆"（DP + 更大的 batch），
通信是它们共同的代价 —— 所以并行策略的本质是**把通信放在最快的链路上**。

# 示例知识库（AI / 计算机方向）

> 拿去试 `设置 → 知识库 → 添加文件…`，或者先用命令行看检索效果：
>
> ```bash
> python tools\kb_try.py --docs examples\kb --queries examples\问法示例.txt
> ```
>
> （`kb_try.py` 不装产品、不改配置、不联网；只打印命中的片段。）

## 文件说明

资料按目录摆好了。设置里点「**添加文件夹…**」选一个文件夹，**整个文件夹就变成一个分组**，
组名就是文件夹名 —— 所以这里要选两次：`examples/kb/AI` → 组「AI」，`examples/kb/工程` → 组「工程」。

| 分组（= 文件夹名） | 文件 | 覆盖什么形状 | 段数 |
|---|---|---|---|
| **AI** | `kb/AI/Transformer基础.md` | 概念 + 公式里的具体数字（512 维 / 8 头 / O(n²d)） | 6 |
| | `kb/AI/微调与显存.md` | **估算类**问题（7B、FP16、24G 卡能不能微调） | 6 |
| | `kb/AI/RAG工程实践.md` | 方法论 + 本项目自己在用的那套（切片 / 别名 / RRF / 评测） | 7 |
| **工程** | `kb/工程/分布式训练笔记.md` | **长文档型**：2,258 字、10 个小节 | 12 |
| | `kb/工程/Git与命令行速查.md` | **命令**类（含 `--soft` 这种带符号的词） | 7 |
| | `kb/工程/参数对照表.md` | **表格型**：3 张表，看表格会不会被切开 | 5 |

一共 **43 片**。不想分组的，用顶部「添加文件…」，它们会落进「**默认**」组（永远排在最后）。

⚠️ **分组只影响设置里那个列表的显示**（和整组的加文件/刷新/删除），**检索永远在全库做** ——
别指望"分了组就更准"。

## 这两份"新形状"要注意什么

**长文档（`分布式训练笔记.md`）**
- 2,258 字切成 12 片：**一片 ≈ 一个小节**，不会把一条问答切两半；
- 检索结果里会显示「《分布式训练笔记.md》› ZeRO 的三个阶段」——
  那个「› 后面」就是"出处"，模型和你都靠它判断这条从哪来；
- 它也是**切片 bug 的发现者**：第一版"见到空行就切"，同一份文档被切成 **24 片**（平均 94 字）。

**表格（`参数对照表.md`）**
- ⚠️ **里面的数字是编的**，只为演示格式，别当真实规格；
- 整张表落在**同一片**里（量化表 434 字一片 —— 超过 400 字是**故意的**，
  因为切开就没法读了）；
- 问「某个格子」很准（`INT4 的 7B 权重占多少`）；
  问「整列对比 / 按某列排序」就别指望 —— 那种问题不该交给检索，自己看表更快。


## 为什么这么写（这几份是"照着规范写的样本"）

1. **一条一片**：每个 `##` 小节就是一条完整的问答，标题单独起一片并成为"出处"
   （检索结果里显示的 `《文件》小节名`）。
2. **每条自足**：不写"如上所述""见上文"—— 模型只看得到命中的那几片。
3. **`常见问法：…` 一行**：这是性价比最高的东西。写的是**用户口语**，不是术语。
   不写的话"换个说法问"直接 0 结果（实测过：整句匹配 0/16，补了之后 94%）。
4. **答案里带可判定的词**：数字、条件、命令。写"尽量小一点"这种，模型只能猜。

⚠️ **`分布式训练笔记.md` 和 `参数对照表.md` 故意没写 `常见问法`** ——
真实的长文档/表格就长这样。所以对它们提"换个说法"的问题时，命中会明显差一些；
这正好是"**内容质量 > 检索技术**"的现场演示（同样的索引，差别只在资料怎么写）。

## 试的时候注意这两件事

- **`对抗训练怎么做` 这几份资料里没有**，但**不会返回 0 条**：检索用的是"二字组 OR"，
  只要有一个二字组撞上（比如"训练"）就会给一个弱相关的片段。
  这**不是 bug**，是词面检索的已知边界（实测：靠"相对首位 0.6"也剪不掉，
  因为首位本身就是弱命中）。真正的兜底是在提示词里写死"资料里没有的不要编" ——
  产品里那句是 `prompts.KB_GUARD`，由代码拼，用户改不到。
- **`七 B 的模型 FP16 要占多少显存`** 这种"中文数字 + 英文缩写"的写法也能中：
  二字组索引对中英混排是透明的。
